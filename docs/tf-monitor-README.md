# TestFlight 多链接名额监控

版本：1.0.1。用于 Surge iOS，仅检查公开TF邀请页，不自动报名，不读取账号、Cookie或认证信息。

## 安装 / 升级

```text
https://raw.githubusercontent.com/zhiaon/Modules/main/tf-monitor.sgmodule
```

模块使用仓库的 `surge_scripts/tf-monitor.js`，脚本更新检查间隔86400秒。**此次修复涉及模块cron配置，必须更新模块本身；仅更新JS不能消除旧版每分钟启动。** 更新后核对脚本 `tf-monitor` 的cron应为 `*/10 * * * *`，不是 `* * * * *`。若运行态仍旧，只停用再启用本模块，不要重启引擎。

已有模块参数可能保留旧值 `5`：请手动改为 `10`。不要重复安装本地和远程两份。发布远程版不会自动替换本机本地版。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `tf_links` | `-` | 最多10个完整公开邀请链接，英文逗号分隔；`-` 不联网 |
| `interval_minutes` | `10` | 原生cron分钟步进，只支持整数1–59 |

推荐 **10、12、15、20、30**：均能整除60。例如10在每小时00、10、20、30、40、50分触发，每小时6次，而非每分钟先启动脚本再判断。

其他值从每小时00分重新计算，不保证跨小时等间隔，例如40在00、40分触发，跨小时只隔20分钟。1–5每小时超过10次，仍可能收到Surge耗电警告；至少6，推荐10。**不再支持旧版60–1440分钟**；无效表达式可能使模块加载失败，不再承诺脚本能替调度器回退。

参数在模块参数界面填写，不把私人链接写进模块或公开提交。不要加引号、标签、其他配置文本。非法链接跳过、重复去重、超过10项忽略。保存参数后等下一cron触发，不立即检查。

## 行为与限制

- 不再每分钟空跑；每次原生cron触发检查链接，最多10项、并发2，每链接最多一次GET。20秒重复执行保护与运行锁保留。
- 升级沿用原状态缓存，不清空已提醒状态。旧版模块使用新JS仍保留旧节流以兼容，但仍须升级模块来降低启动频率。
- 首次开放提醒，持续开放不重报；确认满员/关闭后重新开放才再次提醒。未知页、跳转、非200/超时不当作开放，也不重置已提醒状态。
- 无MITM、新规则、自动报名。通知链接供手动查看，不保证名额/设备资格或报名成功。
- `wake-system=false`，不强制唤醒；后台/锁屏可能延迟，不保证通知展示、准点或必达。历史警告不会被脚本删除。
- 公开英文结构变化时保守不提醒；存储失败保守处理，先保存状态再发通知可能在崩溃/系统抑制时漏一条提醒；缓存锁不是跨实例原子事务。

停用模块即可停止调度；`tf_links=-` 保留低频调度但零网络。

## 验证

Node回归 **82/82**（含原63项）；Surge JSC隔离快照测试通过；本机实际回读为1.0.1、cron `*/10 * * * *`、不强制唤醒，其他脚本注册未变。启动频率由默认60次/小时降为6次/小时。不等于已测得节电百分比；长期锁屏、真实系统通知、后续是否新增警告未作长期观察。

官方依据：https://manual.nssurge.com/scripting/cron.html ：每小时超过10次触发耗电提示。
