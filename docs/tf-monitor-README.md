# TestFlight 多链接名额监控

版本：1.0.0。用于 Surge iOS，仅检查公开 TestFlight 邀请页，不自动报名，不读取账号、Cookie 或认证信息。

## 安装

在 Surge 的模块管理中通过 URL 添加：

```text
https://raw.githubusercontent.com/zhiaon/Modules/main/tf-monitor.sgmodule
```

模块自动使用仓库中的 `surge_scripts/tf-monitor.js`，脚本更新检查间隔为 86400 秒。发布远程版不会替换已安装的本机模块。

## 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `tf_links` | `-` | 最多 10 个完整公开 TestFlight 邀请链接，用英文逗号分隔；`-` 表示不联网 |
| `interval_minutes` | `5` | 每链接检查间隔，整数 1–1440 分钟；无效值回退 5 |

在 Surge 模块参数界面填写自己的链接，不要把私人链接写入模块文件或公开提交。重复代码自动去重，非法项跳过，超过 10 项忽略多余项。

## 行为与限制

- 每分钟轻量调度，各链接按配置间隔独立节流；每轮每链接最多一次 GET，总并发 2。
- 首次确认开放时调用通知；持续开放不重复通知，确认满员或关闭后再次开放才重新通知。
- 未知页面、跳转、请求失败和非 200 响应不视为开放。存储失败时采取保守策略。
- 无 MITM、无新增规则、无自动加入。点击通知后手动查看；页面开放不保证剩余名额或设备资格。
- `wake-system=false`，锁屏、后台限制和网络故障可延后执行；系统通知展示、准点和必达不作保证。
- 识别依据为公开英文页面结构；页面变化可能导致不提醒。先保存通知状态再调用通知 API，崩溃或系统抑制可能漏掉一次提醒；缓存锁不是跨实例原子事务。

停用模块即可停止检查；将 `tf_links` 改为 `-` 则保留轻量调度但不发请求。重新添加同一链接沿用去重记录。

## 验证

发布前复跑现有 Node 离线回归测试 63/63；远程脚本与本机已安装源码逐字节相同。未验证真实名额变化、锁屏长期调度、系统通知展示或报名成功。
